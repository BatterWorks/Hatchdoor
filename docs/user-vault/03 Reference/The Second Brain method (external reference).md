# The Second Brain method (external reference)

"Second brain" is Tiago Forte's name for a practice, and [[The PARA method (external reference)|PARA]] is his scheme for organizing one. This page describes the practice for anyone deciding whether to keep a second brain and how, and links to the primary source.

## The core idea

A second brain is a system outside your memory that you trust to hold what is worth keeping: ideas, insights, quotes, references. Its purpose is to free your working memory, so you spend it on thinking and stop spending it on remembering. Forte argues you need one because of an "information overload" that biological memory was never built to handle.

## The CODE method

Forte describes four steps for turning raw information into something you can use later:

| Step | What it means |
| --- | --- |
| **Capture** | Keep what resonates when you meet it, as a note, a highlight or a screenshot. Do not trust yourself to remember it or find it again. |
| **Organize** | File what you captured by how actionable it is, whatever its topic or source. [[The PARA method (external reference)\|PARA]] is Forte's way of doing this. |
| **Distill** | Summarize in passes down to the essence, so reading the note later takes seconds where the original research took hours. |
| **Express** | Turn the notes into something you share, such as a document, a decision or a piece of work, so they do not sit unused. |

## Second Brain vs. PARA

The two do not compete. A second brain is the whole practice: capture, keep, distill, and in the end use what you kept. PARA is one part of it, Forte's answer to where captured things live. A Vault can follow CODE without PARA's four folders, and it can use PARA's folders without CODE. Forte designed them as a pair, and most of his writing treats them that way.

## Why it's meant to work across any tool

Like PARA, a second brain needs no particular tool. Forte's examples include notebooks, cloud drives and note apps. The practice does not assume an app owns your notes. It assumes you have a lasting place to keep them and a habit of using it.

## How this shows up in a Hatchdoor Vault

Plain Markdown files are the lasting, portable store the practice asks for. Hatchdoor adds a second party who can act on that store. An agent connected over MCP can capture material into a note when you ask, distill a page by rewriting or trimming it, and draft a summary or a report from what is already there. It does all of this through the checked read and write tools in [[MCP tools reference]]. You still decide what is worth keeping, and you review what changed in the Web UI. The agent takes over much of the routine work of Organize and Distill.
