# The PARA method (external reference)

PARA is a way to organize a Vault's folders. It has nothing to do with Hatchdoor or with agents. This page describes the method for anyone deciding how to lay out a new Vault, and links to the primary source.

## The four categories

PARA sorts everything into four categories, from the most actionable to the least:

| Category | Definition | 
| --- | --- |
| **Projects** | "Short-term efforts (in your work or personal life) that you take on with a certain goal in mind". Examples: completing a webpage design, buying a computer, finishing a language course. |
| **Areas** | "Important parts of your work and life that require ongoing attention". Examples: Marketing and Product Management at work, Health, Finances and Home in private life. |
| **Resources** | Topics "you're interested in and learning about", such as graphic design, gardening or photography, with no outcome attached. |
| **Archives** | "Anything from the previous three categories that is no longer active, but you might want to save for future reference". Examples: completed projects, areas you dropped, interests you gave up. |

## The two distinctions that matter

**Projects vs. Areas** is the one people get wrong most often. The difference is how long the thing lasts, whatever its importance. An Area is a responsibility that "continues indefinitely", and a Project has an end. Forte's example is listing "strategic planning" or "vacations" as Projects, which is a mistake because they never finish. Anything that "will end or change" is a Project. Anything you maintain indefinitely is an Area.

**Resources vs. Archives** is simpler. A Resource is a topic you still work with. An Archive is a former Project, Area or Resource that you keep only to look things up later.

## Why it's meant to work across any tool

Forte designed PARA to apply "across any platform": a computer's file system, cloud storage or a note-taking app. It sorts by how actionable something is, which no tool has to support. PARA is four folders and a filing habit.

## How this shows up in a Hatchdoor Vault

[[How to choose a folder layout]] suggests a PARA variant for a new Vault: `10-topics/`, `20-projects/`, `30-areas/`, `40-reference/` and `90-archive/`, with Topics in the role of Resources. It adds a numbered `00-inbox/` for unsorted capture, which PARA does not specify. Nothing in Hatchdoor requires this or any other layout.

Hatchdoor meets PARA in one place. `archive_note`, as an MCP tool and as an action in the Web UI, moves a note into the Vault's archive folder in one step, which is what PARA's Archives category asks for. See [[MCP tools reference]]. PARA and Hatchdoor's [[The layer system|layer system]] solve different problems and work together. PARA decides which folder a note lives in. A layer decides whether the note shows up in default search, whichever PARA folder holds it.
