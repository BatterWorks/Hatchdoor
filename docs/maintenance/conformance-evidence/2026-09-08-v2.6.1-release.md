# MCP conformance run — 2026-09-08 (v2.6.1 release evidence)

Clean release evidence for the **41-tool** catalogue on `development`, taken as
the pre-merge gate for the v2.6.1 release PR into `main`. Supersedes
[`./2026-09-03-v2.6.0-release.md`](./2026-09-03-v2.6.0-release.md), which
verified the same boundary at 40 tools. Four MCP-facing changes have landed
since that run, so it no longer describes the surface being shipped:

- `query_notes` returns (#274), taking the catalogue from 40 to 41. It is a
  read tool, so it appears in both postures.
- A refused tool call now carries `ok: false` in its structured result (#255).
  Every tool's published `outputSchema` is unchanged.
- `get_stats` reports `hatchdoor_version`, and the server instructions and
  `serverInfo` carry the running version (#263, #264).
- `update_frontmatter` edits a note's frontmatter in place (#257), and the
  attachment tools accept any non-Markdown file already in a Vault (#247).

Procedure: [`../mcp-conformance-run.md`](../mcp-conformance-run.md).

- Runner: `@modelcontextprotocol/conformance` **0.2.0-alpha.11** via `npx -y`
  (`--version` confirmed at the start of this run), the same version the
  superseded run used.
- Server: local dev build (`just dev-start`, `clean` vault profile) reporting
  version `2.6.1`, `http://127.0.0.1:42824/mcp`, reached through the documented
  header-injecting proxy on `127.0.0.1:42999`. The proxy's target and token
  were verified against this build before the suite was invoked.
- Baseline: [`../conformance-baseline.yml`](../conformance-baseline.yml),
  reviewed for this run and **unchanged**. No entry went stale — the framework
  exits non-zero when a baselined scenario passes, and all four runs exited 0 —
  and this release's added tool, added result field and rewritten tool
  descriptions needed no new entry.

## Catalogue under test

Confirmed against the running build before the suite was invoked, and every
advertised tool carries an `outputSchema`:

- Write-enabled: **41** tools, including `query_notes`.
- Read-only: **18** tools. That is one more than the 17 of the 40-tool run, and
  `query_notes` is the difference: it selects notes from the read model and
  involves no embedding or mutation, so it is correctly ungated. The rest of
  the read-only list is unchanged.

## Command lines

```bash
npx -y @modelcontextprotocol/conformance@0.2.0-alpha.11 server \
  --url http://127.0.0.1:42999/mcp \
  --expected-failures docs/maintenance/conformance-baseline.yml \
  --requirements 2025-11-25 --output-dir <dir>
npx -y @modelcontextprotocol/conformance@0.2.0-alpha.11 server \
  --url http://127.0.0.1:42999/mcp \
  --expected-failures docs/maintenance/conformance-baseline.yml \
  --requirements 2026-07-28 --output-dir <dir>
```

Run once per write posture (`HATCHDOOR_MCP_WRITE_ENABLED=true|false`, server
restarted between postures via `just dev-start`).
