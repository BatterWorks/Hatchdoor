# MCP conformance run, 2026-10-02 (v2.7.0 release evidence)

Clean release evidence for the **46-tool** catalogue on the v2.7.0 version-bump branch (`docs/release-v2.7.0`), taken as the conformance item of the release checklist. Supersedes [`./2026-09-08-v2.6.1-release.md`](./2026-09-08-v2.6.1-release.md), which verified the boundary at 41 tools. The MCP-facing changes since that run:

- `evaluate_saved_query` (#277), a read tool, so it appears in both postures.
- `rename_tag` (#242), `delete_tag` (#258), `publish_recovery_branch` (#80) and `create_upload_link` (#310, #303), all write tools.
- `get_attachment` returns a self-authenticating download link (#310), `get_note` lists a note's saved queries (#277), `list_vaults` reports `link_style`, `link_path_form` and `index_turn` (#357, #383), and `search_notes` can report `"mode": "tag"` (#354).
- Structured errors for failed `batch` items and oversized base64 attachments, and narrower refusals during legacy environment cleanup (#327). Rewritten descriptions for the collection reads and the note writers (#259, #260).

Procedure: [`../mcp-conformance-run.md`](../mcp-conformance-run.md).

- Runner: `@modelcontextprotocol/conformance` **0.2.0-alpha.11** via `npx -y` (`--version` confirmed at the start of each posture), the same version as the superseded run.
- Server: local dev build (`just dev-start`, `clean` vault profile) logging `Hatchdoor 2.7.0` at startup, `http://127.0.0.1:42824/mcp`, reached through the documented header-injecting proxy on `127.0.0.1:42999`.
- Baseline: [`../conformance-baseline.yml`](../conformance-baseline.yml), reviewed for this run and **unchanged**. No entry went stale: the framework exits non-zero when a baselined scenario passes, and all four runs exited 0. The added tools and result fields needed no new entry.

## Catalogue under test

Confirmed against the running build, and every advertised tool carries an `outputSchema`:

- Write-enabled: **46** tools.
- Read-only: **19** tools, one more than the 18 of the 41-tool run. `evaluate_saved_query` is the difference: it evaluates a saved query from the read model and mutates nothing, so it is correctly ungated. The other new tools are all write tools and are absent in this posture.

  --url http://127.0.0.1:42999/mcp \
  --expected-failures docs/maintenance/conformance-baseline.yml \
  --requirements 2025-11-25 --output-dir <dir>
npx -y @modelcontextprotocol/conformance@0.2.0-alpha.11 server \
  --url http://127.0.0.1:42999/mcp \
  --expected-failures docs/maintenance/conformance-baseline.yml \
  --requirements 2026-07-28 --output-dir <dir>

Run once per write posture (`HATCHDOOR_MCP_WRITE_ENABLED=true|false`, server restarted between postures via `just dev-stop` and `just dev-start`).
