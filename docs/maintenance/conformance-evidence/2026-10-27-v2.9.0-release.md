# MCP conformance run, 2026-10-27 (v2.9.0 release evidence)

Clean release evidence for the **51-tool** catalogue on the v2.9.0 version-bump branch (`docs/release-v2.9.0`), taken as the conformance item of the release checklist. Supersedes [`./2026-10-10-v2.8.0-release.md`](./2026-10-10-v2.8.0-release.md). The 2.8.1 and 2.8.2 patch releases recorded no run. The MCP-facing changes since the v2.8.0 run:

- `create_upload_link` accepts an optional `commit_summary` (#598).
- `list_vaults` adds `docs` to each Vault status error the manual explains (#583).
- The client name a session sends at `initialize` is recorded in the `Hatchdoor-Origin:` trailer of the commits its writes produce (#570). This changes no message on the wire.
- `query_notes` and `find_text` no longer match a note named after the folder in `path_prefix` (#584). Result shapes are unchanged.

Procedure: [`../mcp-conformance-run.md`](../mcp-conformance-run.md).

- Runner: `@modelcontextprotocol/conformance` **0.2.0-alpha.11** via `npx -y` (`--version` confirmed at the start of the run), the same version as the superseded run.
- Server: local dev build (`just dev-start`, `messy` vault profile) logging `Hatchdoor 2.9.0` at startup, `http://127.0.0.1:42824/mcp`, reached through the documented header-injecting proxy on `127.0.0.1:42999`.
- Baseline: [`../conformance-baseline.yml`](../conformance-baseline.yml), reviewed for this run and **unchanged**. No entry went stale: the framework exits non-zero when a baselined scenario passes, and all four runs exited 0.
