# MCP conformance run, 2026-11-14 (v2.10.0 release evidence)

Clean release evidence for the **52-tool** catalogue on the v2.10.0 version-bump branch (`docs/release-v2.10.0`), taken as the conformance item of the release checklist. Supersedes [`./2026-10-27-v2.9.0-release.md`](./2026-10-27-v2.9.0-release.md). The MCP-facing changes since the v2.9.0 run:

- New read-only tool `find_link_problems` lists one Vault's broken links, orphans or dead ends, paged (#575).
- A `batch` write may pass `"from_batch"` as its `expected_content_hash`, checked against an earlier read in the same batch (#599).
- The `initialize` instructions point an agent at the manual page *How to work in a Vault as an agent* before its first write (#568).
- On the `2026-07-28` revision a refused tool call answers HTTP 200 with the JSON-RPC error in the body, where it was HTTP 400; the error code and message are unchanged (#621).
- `create_vault` and `edit_vault` refuse a folder outside the Vault mount with `vault_path_outside_mount` (#700).
- MCP concurrency slots stay taken until the reply ends on both revisions, and write refusals are readable (#632).
- An unknown tool always gets the "Unknown MCP tool" error, even while the search model loads (#733).
- While the search model loads, or after its setup failed, the session instructions and tool refusals say so, instead of asking to accept the Gemma terms (#762, #774, #775, #779).
- `Bearer` is accepted in any case, followed by any number of spaces (#629).

Procedure: [`../mcp-conformance-run.md`](../mcp-conformance-run.md).

- Runner: `@modelcontextprotocol/conformance` **0.2.0-alpha.11** via `npx -y` (`--version` confirmed at the start of the run), the same version as the superseded run.
- Server: local dev build (`just dev-start`) logging `Hatchdoor 2.10.0` at startup, `http://127.0.0.1:42824/mcp`, reached through the documented header-injecting proxy on `127.0.0.1:42999`.
- Baseline: [`../conformance-baseline.yml`](../conformance-baseline.yml), **unchanged**. No entry went stale: the framework exits non-zero when a baselined scenario passes, and all four runs exited 0.

## Catalogue under test

Counted by `just conformance` against the running build:

- Write-enabled: **52** tools.
- Read-only: **25** tools.

Each is one more than the v2.9.0 run: `find_link_problems`, which is read-only.

```bash
  --requirements 2025-11-25 --output-dir <dir>

  --expected-failures docs/maintenance/conformance-baseline.yml \
  --requirements 2026-07-28 --output-dir <dir>
```

Run once per write posture by `just conformance`, which restarts the backend with `HATCHDOOR_MCP_WRITE_ENABLED=true`, then `false`.
