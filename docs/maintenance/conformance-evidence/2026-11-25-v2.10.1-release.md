# MCP conformance run, 2026-11-25 (v2.10.1 release evidence)

Clean release evidence for the **52-tool** catalogue on the v2.10.1 version-bump branch (`docs/release-v2.10.1`), taken as the conformance item of the release checklist. Supersedes [`./2026-11-14-v2.10.0-release.md`](./2026-11-14-v2.10.0-release.md). The MCP-facing changes since the v2.10.0 run:

- `edit_vault` refuses an identity change on a managed Git Vault whose old checkout no longer matches what Hatchdoor cloned, with `checkout_set_aside_failed` and a message naming the folder to move by hand, where it used to move that checkout aside uncommitted. Once an identity change is saved, enabling the Vault clones the new source at once and its Git status reads `pending` (#802).
- The bearer-token gate in `src/mcp/routes.rs` reads the live MCP configuration inline instead of through a helper, to satisfy a lint Rust 1.100 added. Its order and answers are unchanged.
- The build moved from Rust 1.97.1 to 1.100.0.

Procedure: [`../mcp-conformance-run.md`](../mcp-conformance-run.md).

- Runner: `@modelcontextprotocol/conformance` **0.2.0-alpha.11** via `npx -y` (`--version` confirmed at the start of the run), the same version as the superseded run.
- Server: local dev build (`just dev-start`) of the bump branch at version 2.10.1, `http://127.0.0.1:42824/mcp`, reached through the documented header-injecting proxy on `127.0.0.1:42999`.
- Baseline: [`../conformance-baseline.yml`](../conformance-baseline.yml), **unchanged**. No entry went stale: the framework exits non-zero when a baselined scenario passes, and all four runs exited 0.
