# MCP conformance run, 2026-10-10 (v2.8.0 release evidence)

Clean release evidence for the **51-tool** catalogue on the v2.8.0 version-bump branch (`docs/release-v2.8.0`), taken as the conformance item of the release checklist. Supersedes [`./2026-10-02-v2.7.0-release.md`](./2026-10-02-v2.7.0-release.md), which verified the boundary at 46 tools. The MCP-facing changes since that run:

- `read_docs` and `search_docs` (#421), `find_text` (#500), `get_note_outline` and `get_note_section` (#502). All five are read tools, so they appear in both postures.
- `search_notes` hits are compact by default, with a `detail` argument and an `outputSchema` that describes both shapes (#501). Hit `content` keeps its code fences and `snippet` leaves code out (#532).
- `get_note` returns the note's frontmatter under `metadata`, or `null` when it does not parse (#521). `list_vaults` reports `search: "stale"` with `capabilities.search: true` during a reindex (#483) and no longer carries `legacy_migration_recovery` (#427).
- A refused call whose code the manual explains carries a `docs` field (#423). `create_vault` and `edit_vault` name the Vault in the way in a `vault_path_overlap` refusal (#495).
- The opening instructions point to the What's new page (#424) and, once on an upgraded install, carry the usage report sentence (#479).

Procedure: [`../mcp-conformance-run.md`](../mcp-conformance-run.md).

- Runner: `@modelcontextprotocol/conformance` **0.2.0-alpha.11** via `npx -y` (`--version` confirmed at the start of each posture), the same version as the superseded run.
- Server: local dev build (`just dev-start`, `messy` vault profile) logging `Hatchdoor 2.8.0` at startup, `http://127.0.0.1:42824/mcp`, reached through the documented header-injecting proxy on `127.0.0.1:42999`. The superseded run used the `clean` profile; the suite exercises the protocol boundary and no Vault content, and every total below matches it.
- Baseline: [`../conformance-baseline.yml`](../conformance-baseline.yml), reviewed for this run and **unchanged**. No entry went stale: the framework exits non-zero when a baselined scenario passes, and all four runs exited 0. The added tools and result fields needed no new entry.

## Catalogue under test

Confirmed against the running build with `tools/list`, and every advertised tool carries an `outputSchema`:

- Write-enabled: **51** tools.
- Read-only: **24** tools, five more than the 19 of the 46-tool run. The five new tools are the difference: each reads and mutates nothing, so it is correctly ungated.
