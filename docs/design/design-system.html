§05

Sidebar (Explorer)

Three zones: a fixed rail of whole-vault destinations, the scrolling note navigation, and the create action pinned at the bottom. Only the middle scrolls — the rail and footer never move. The rail lives inside the sidebar rather than the topbar on purpose: the topbar’s four mobile slots are a hard budget, and the drawer sits outside it.

Folders use a CSS-only chevron caret that rotates open. Notes show a mono index — that is what tells note rows apart from folder rows without changing size or weight. Active note: hot-orange left rail + hot-soft background + bolded, and it is canonical in the tree only. Applying it in the recency lists too is what made one note light up in three places at once.

Section heads take a label, a rule, and a mono count. A collapsible section adds the same caret the folder rows use, so a foldable thing reads the same way wherever it appears. Section numerals are optional — use them only where the order carries meaning.

§08

Metadata grid

Sits between title block and body. Four-column property grid, hairline rules top + bottom, no border-radius. Tag chips use hot-soft background with hot text — hover inverts.

The heading is the disclosure. There is no separate Show/Hide button; clicking the “Properties” line folds the grid, using the same caret as the sidebar folder rows. Markup is button inside heading, not the reverse — a heading is flow content and is invalid inside a button, and this keeps the entry in the document outline. The hit area is the full line.

§10

Prose & inline elements

Reading measure: uncapped. This document previously specified max-width: 36rem on the note body; the app has always rendered full width, about 100 characters at 1440px. Capping was considered and rejected. Nearly every non-prose block here is a bordered box — .table-wrap, .callout, .code-block — so a narrow text column beside full-width boxes reads as broken alignment rather than as hierarchy, and capping every block uniformly instead pushes tables and diagrams into horizontal scrolling much sooner. The app is authoritative; this document was stale.

Body paragraphs use Newsreader serif at 1.18rem / lh 1.62. Inline links underline with a 2px hot rail (hovering inverts: hot fill, paper text). Inline code uses a paper-2 surface. Broken links show dashed underline in error color.

The mornings have turned colder than they should be for May, and the cordons along the south wall are flowering anyway. I went out at half-six to see whether the frost had taken the blossom — it had not — but the bees were absent and the wasps were already on the cherries.

§19

Popover menu

The topbar “more” button opens this. On desktop it anchors to the trigger. On mobile it becomes a bottom-sheet (CSS variant in implementation).

Rows are borderless. Only the popover carries a border — a box per row inside a bordered container is the “boxes in boxes” nesting issue #8 objected to. The border is kept and made transparent rather than removed, so a row does not shift when :active paints it hot. Hover fills with --paper-2. Long menus group with .menu-divider rather than growing into an undifferentiated wall.

§20

Inline editing

Clicking a block swaps it for a textarea holding that block’s own markdown. The affordance is a rule in the left gutter, not a fill and not a box: it reuses the device the list bullet already uses, so it reads as content rather than as a control, and it costs no horizontal space, so nothing reflows.

It is drawn with ::after because ::before is already the list marker, and .editable-block is the rendered element itself. Wrapping blocks in a div would sit between a ul and its li children and break every marker rule.

Resting: no mark at all, so a note reads as a document.

Hovered: a 1px hot hairline at 45% in the gutter.

Active: the same device at 2px and full weight. No ring, no fill, so it does not fight the borders callouts and tables already carry.

.editable-block.editable-block:hover.editable-block.is-active--edit-gutter

The gutter is borrowed, not owned

The note body sits flush against its container. The space the rule occupies is .note-pane’s padding, which is 56px on desktop and 16px on a phone, and that element is overflow-x: hidden. Clipping happens at the padding box, so a negative-margin rule survives, but the offset has to be a token rather than a constant.

Block input: match the metrics, never the transforms

The input inherits family, size, weight, line-height and colour from the block it replaces, and explicitly resets text-transform. Three rendered styles in this system uppercase their text — h1, h3, h6, callout titles and table headers — and an input that inherited that would show the typist a different string than the one being written to the file.

The line’s markdown prefix is measured and hung into the gutter, so the visible text does not move on entry. A fixed hang cannot work: - is about 9px while the bullet it replaces is inset 22.4px, and the width varies per prefix. On a phone the hang is clamped to the pane’s 16px, so a long prefix shifts slightly rather than being clipped.

Table rows are overlaid, not replaced

A tr may not contain a textarea, and swapping its cells for one lets every column resize on entry and again on exit, because widths derive from content. The cells stay in the flow holding the grid still, and the input is laid over the row from inside its first cell.

Touch

A tap reads; a long press (500ms, cancelled by 10px of movement) enters a block. Tap-to-edit would raise the keyboard on every stray touch, and reading is the dominant mode on a phone. The gutter rule is drawn persistently at low opacity on coarse pointers, because a long press is otherwise an invisible gesture.

§21

Save state

Autosave removed the Save button, and with it the only evidence a user had that their writing survived. In a vault with agent co-writers and git sync, that evidence is the trust surface of the whole feature, so it gets a permanent slot beside Edit.

It states what is true now rather than announcing an event: “Saved 14:32”, not “Saved!”. The failure state is a click target that opens the conflict review.

Frontmatter values edit in place for the same reason blocks do: changing a tag should not require dropping the whole note into source mode. The input follows .field-input. §26

Icons

Material Symbols — Sharp variant only. Sharp is drawn with right angles and squared terminals, which is the only mainstream icon language that agrees with the zero-radius rule. Outlined and Rounded do not; do not mix them in. Licensed Apache 2.0, attributed in THIRD_PARTY_NOTICES.md.

Inlined, never installed. Icons live as components in frontend/src/components/icons.tsx with the path data copied verbatim. No icon font, no npm package, no CDN request — this keeps the PWA’s offline path clean and satisfies ADR-13. Adding one means pasting a Sharp SVG, not adding a dependency.

Each icon sizes to 1em and paints with currentColor, so callers control both through ordinary font-size and color. All are aria-hidden: every icon sits inside a control that carries its own accessible name.
